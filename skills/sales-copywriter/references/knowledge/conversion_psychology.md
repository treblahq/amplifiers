# Conversion Psychology

> **Objective:** Apply cognitive biases and anxiety reduction to increase conversion across pages and funnels.

## Overview

This document is a focused playbook on **Conversion Psychology**.

Primary job: apply cognitive biases and anxiety reduction to increase conversion across pages and funnels.

- Focus: packaging and framing — the offer is the conversion engine (not the page design).

## Key concepts

- Buying drivers (loss, gain, identity, status, safety)
- Most useful biases (anchoring, social proof, reciprocity, scarcity)
- Reducing friction and anxiety (clarity, predictability, control)
- Trust architecture (proof, guarantees, transparency)
- Decision-making: simplicity and micro-commitments
- Objections: how to anticipate and neutralize

## Execution framework

1. **Map the prospect’s emotional state (fear/desire)**
   - Intent: Choose one emotional driver and write in the customer’s language; don’t mix emotions in the same asset.
   - Output: One primary driver (fear/desire/status/safety) + a short language bank (10 phrases the customer uses).
   - Pitfall: Mixing multiple emotions in the same asset (confusing tone and desire).
2. **List beliefs and objections by funnel stage**
   - Intent: List the top objections and map each to a fix (proof, stack item, guarantee, clarification) so the asset pre-empts doubt.
   - Output: An objection map (top 10) → one fix per objection (proof, bonus, guarantee, clarification).
   - Pitfall: Inventing bonuses/claims without mapping objections (the asset never resolves doubt).
3. **Choose 2–3 primary biases (avoid overload)**
   - Intent: Pick 2–3 biases that match the stage and reduce anxiety; avoid stacking so many signals that it feels manipulative.
   - Output: A bias plan: chosen biases + where they appear (headline, proof, guarantee, CTA).
   - Pitfall: Stacking too many biases at once — it feels manipulative and triggers skepticism.
4. **Design proof (what, where, in what order)**
   - Intent: Collect real proof (screenshots, numbers, demos) and place it with context.
   - Output: A proof pack: 3–10 assets (screenshots, numbers, demos) mapped to key claims.
   - Pitfall: Using proof with no context (no baseline, timeframe, or attribution).
5. **Reduce friction (UX, copy, clarity, policies)**
   - Intent: Reduce friction and anxiety: remove steps/fields, clarify terms, and make the next action obvious.
   - Output: A friction audit + prioritized fixes (UX, copy, clarity, policies) with expected impact.
   - Pitfall: Removing friction in the wrong place (or adding new friction) — you lower trust while trying to raise CVR.
6. **Create micro-commitments before the decision**
   - Intent: Add micro-commitments (small yeses) that build belief and momentum before the main decision.
   - Output: A micro-commitment ladder: small actions that build belief before the main CTA, with KPIs.
   - Pitfall: Adding steps that feel like chores (or asking for purchase too early) — micro-commitments become friction.
7. **Test variations with a hypothesis (one bias per test)**
   - Intent: Define the hypothesis, variants, window, and decision criteria before running it.
   - Output: A bias plan: chosen biases + where they appear (headline, proof, guarantee, CTA).
   - Pitfall: Stacking too many biases at once — it feels manipulative and triggers skepticism.

## Common mistakes

- An aggressive promise without a mechanism (refund magnet).
- Fake urgency/scarcity (short-term CVR, long-term brand damage).
- Bonuses that compete with the core (decision friction).
- Price revealed before value is anchored (sticker shock).

## Tests and measurement

### Tests

- Test bonus naming: functional name vs “high perceived value” name (same bonus).
- Test stack order: objection-first bonuses vs acceleration-first bonuses.
- Test value anchoring sequence: alternatives/cost-of-inaction before price vs after.
