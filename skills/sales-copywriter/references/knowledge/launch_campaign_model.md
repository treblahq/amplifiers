# Launch Campaign Model

> **Objective:** Apply launch logic with warm-up content, a buying window, and a close with real urgency.

## Overview

This document is a focused playbook on **Launch Campaign Model**.

Primary job: apply launch logic with warm-up content, a buying window, and a close with real urgency.

- Focus: packaging and framing — the offer is the conversion engine (not the page design).

## Key concepts

- Pre-launch structure (content) and cart open/close
- What must happen during warm-up (belief and proof)
- How to structure the offer and conditions in the window
- Urgency and scarcity with integrity
- Operations: support, FAQ, and objection handling
- Post-launch: onboarding and ladder

## Execution framework

1. **Define the launch promise, mechanism, and proof**
   - Intent: Collect real proof (screenshots, numbers, demos) and place it with context.
   - Output: A proof pack: 3–10 assets (screenshots, numbers, demos) mapped to key claims.
   - Pitfall: Using proof with no context (no baseline, timeframe, or attribution).
2. **Plan capture (list) and lead magnet**
   - Intent: Create a lead magnet that qualifies: one promise, one quick win, one bridge to the next step.
   - Output: A lead magnet brief + landing promise + delivery email + bridge CTA to the next step.
   - Pitfall: A generic lead magnet that attracts low-intent leads (list grows, revenue doesn’t).
3. **Create warm-up content (belief → proof → method)**
   - Intent: Map the funnel stages end-to-end (objective, CTA, KPI per stage) and enforce message-match across the journey.
   - Output: A stage map: ad → page → checkout → backend, with objective, CTA, KPI, and message-match notes per stage.
   - Pitfall: Optimizing one stage in isolation and breaking message-match (the journey stops making sense).
4. **Prepare the sales page and checkout**
   - Intent: Structure the visual path (fold-by-fold) to reduce friction and build trust.
   - Output: A checkout friction audit + a prioritized fix list (fields, trust, payments, copy).
   - Pitfall: Adding more elements instead of removing friction (fields, distractions, ambiguity).
5. **Execute the open (emails, lives, remarketing)**
   - Intent: Create a sequence with one goal per email + trigger + single primary CTA.
   - Output: A sequence map (entry/exit event, email-by-email angles, CTAs, and triggers).
   - Pitfall: Multiple CTAs per email and “newsletter vibes” with no single objective.
6. **Execute the close (real urgency + final proof)**
   - Intent: Collect real proof (screenshots, numbers, demos) and place it with context.
   - Output: A conditions policy: the constraint, how it’s verified, and what changes when the window ends.
   - Pitfall: Fake scarcity/urgency — short-term CVR, long-term brand damage and higher refunds.
7. **Review results and iterate the next launch**
   - Intent: Run short cycles: analyze → pick the bottleneck → test → consolidate learnings.
   - Output: A weekly loop: bottleneck → test → learnings → consolidation.
   - Pitfall: Looking at aggregate numbers without segmentation/cohorts — you can’t see the real bottleneck.

## Launch reference (warm-up → open → close)

Use this as a default structure for a conversion-driven launch with real urgency.

### Timeline (example)

```text
T-21 to T-7: list growth + warm-up (belief + proof)
T-6 to T-1: pre-launch content (teach + belief breaks + proof)
T0: cart open (offer + conditions)
T+1 to T+3: objections + proof + social proof + FAQs
T+4: close (real deadline + final proof)
T+5+: onboarding + quick win + ladder/continuity
```

### What warm-up must accomplish

- Install the mechanism (why it works) and remove the default belief that keeps people stuck.
- Create proof cadence (small proofs often, not one huge proof at the end).
- Pre-handle the top objections before the buying window opens.

### Open/close operations checklist

- Support readiness: FAQs, scripts, SLA, escalation path.
- Checkout reliability: payment methods, approval rate monitoring, fallback plans.
- Tracking readiness: events/pixels + attribution checks before spend ramps.
- Urgency integrity: deadline + what changes after (price/bonus/access) and how it’s enforced.

### Decision rules

- If warm-up has good engagement but low belief: strengthen mechanism clarity + proof cadence.
- If open has clicks but low purchase: fix offer clarity/stack + checkout friction before adding pressure.
- If close converts but refunds spike: tighten expectations, scope, and onboarding quick win.

## Common mistakes

- An aggressive promise without a mechanism (refund magnet).
- Fake urgency/scarcity (short-term CVR, long-term brand damage).
- Bonuses that compete with the core (decision friction).
- Price revealed before value is anchored (sticker shock).
- Optimizing visuals while ignoring payment friction (methods, approval rate).
- Bumps/upsells that feel unrelated (low take rate and trust loss).
- Overloading the checkout with copy (more reading = more doubt).

## Tests and measurement

### Metrics

| Metric | What it indicates | How to use |
|---|---|---|
| Upgrade rate | Progression health | Offer the next step based on behavior and readiness; reduce friction. |

### Tests

- Test bonus naming: functional name vs “high perceived value” name (same bonus).
- Test stack order: objection-first bonuses vs acceleration-first bonuses.
- Test value anchoring sequence: alternatives/cost-of-inaction before price vs after.
- Test upgrade timing: behavior-triggered vs time-based (measure upgrade rate + refunds).
- Test the next-step framing: “upgrade” vs “next milestone” language (same offer).
