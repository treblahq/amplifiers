# VSL Script Structure

> **Objective:** Write VSL scripts with rhythm, proof, and CTA — converting without relying on “charisma”.

## Overview

This document is a focused playbook on **VSL Script Structure**.

Primary job: write VSL scripts with rhythm, proof, and CTA — converting without relying on “charisma”.

- Focus: reduce friction, increase trust, and keep message-match from ad → page → decision.

## Key concepts

- Structure by blocks and timing
- Drivers: identification, contrast, mechanism, proof, real urgency
- How to insert proof in doses (not only at the end)
- How to answer objections inside the script
- How to write for teleprompter without sounding read
- Recording checklist (audio, light, setting)

## Execution framework

1. **Write the verbal hook (spoken headline)**
   - Intent: Write a one-line pattern interrupt that creates tension/curiosity; generate variations and test.
   - Output: 10–25 hook lines, tagged by driver/angle, each with 1 suggested proof asset.
   - Pitfall: Writing “clever” lines without a clear promise, audience, or proof.
2. **Identification: audience symptoms and context**
   - Intent: Define a single segment with pain, context, and language.
   - Output: An ICP one-pager: segment, context, pains, language, buying triggers, and disqualifiers.
   - Pitfall: Targeting everyone (or writing a generic persona) — the copy can’t be specific, so conversion drops.
3. **Amplification: cost of inaction (without fearmongering)**
   - Intent: Translate the problem into consequences and costs (time, money, status, energy) without exaggeration.
   - Output: A pain map: symptoms → consequences → desired state, plus a language bank.
   - Pitfall: Describing the problem at a surface level (symptoms) without consequences and real context — it doesn’t feel urgent.
4. **Mechanism: why it works (simple)**
   - Intent: Explain why it works and why it’s different from the market’s default approach.
   - Output: A 1–3 bullet explanation of *why this works* (and why the default approach fails).
   - Pitfall: Naming a mechanism without explaining how it works in plain language.
5. **Proof: cases, numbers, demonstration**
   - Intent: Collect real proof (screenshots, numbers, demos) and place it with context.
   - Output: A proof pack: 3–10 assets (screenshots, numbers, demos) mapped to key claims.
   - Pitfall: Using proof with no context (no baseline, timeframe, or attribution).
6. **Offer: what it is, who it’s for, bonuses, guarantee**
   - Intent: Package the offer: core + bonuses + terms + urgency/scarcity (only if real).
   - Output: An offer stack with function-based bonuses + guarantee + real conditions.
   - Pitfall: A vague or overly broad guarantee — it increases refunds and attracts the wrong buyers.
7. **CTA: clear, repeated instruction (right moment)**
   - Intent: Define one next step and phrase it as verb + outcome + what happens next; repeat it at the right moment.
   - Output: One CTA phrased as verb + outcome + next step (what happens after the click).
   - Pitfall: Competing CTAs or a CTA that doesn’t match the stage (too much friction too soon).

## What makes a VSL sell (not just retain)

- Clear pain (fast identification).
- Real consequences (cost of inaction) without fear theatrics.
- A logical next step (your offer feels inevitable).
- Authority via clarity (explain common mistakes, not credentials).
- Risk reduction (who it’s for, who it’s not for, guarantee scope).

## Script phases (practical timing)

### Phase 1 — Attention + connection (0–20%)

- Verbal hook (spoken headline).
- Identification (symptoms, situations, doubts).
- Amplification (future cost if nothing changes).

### Phase 2 — Belief + solution (20–80%)

- Belief break: myth → truth (what the market gets wrong).
- Introduce the mechanism (why it works).
- Give a micro-win (a small but real piece of value).
- Insert proof in doses (cases, numbers, demonstrations).

### Phase 3 — Offer + close (80–100%)

- Offer details (what it is, for whom, what happens next).
- Anchoring + price (if applicable).
- Guarantee + FAQ.
- Single CTA instruction.

## Production checklist (minimum viable)

- Audio quality > video quality (use a decent mic).
- Face well-lit (avoid harsh shadows).
- Edit dead air (keep rhythm) without feeling “over-produced”.
- Subtitles for silent viewers (clean, readable).

## Compliance flags (if you’re in a regulated market)

- Avoid guarantees of outcome.
- Avoid specific money promises.
- Avoid sensationalism as the main tactic.
- Use clear disclaimers and expectation alignment.

## Common mistakes

- Confusing *hook* (opening line) with *angle* (persuasion thesis).
- Writing hooks that don’t imply a promise or tension (they read like facts).
- Not pairing hooks with proof assets (so CTR is driven by hype, not belief).
- Saving hooks without tags (driver, stage, avatar, proof type) — the library becomes unusable.
- An aggressive promise without a mechanism (refund magnet).
- Fake urgency/scarcity (short-term CVR, long-term brand damage).
- Bonuses that compete with the core (decision friction).
- Price revealed before value is anchored (sticker shock).

## Tests and measurement

### Metrics

| Metric | What it indicates | How to use |
|---|---|---|
| 25%/50% watch rate | Retention | Tighten the first 60s; reduce fluff; strengthen proof cadence. |
| CTA click rate | Pitch clarity | Align CTA to promise; place the button at the pitch moment. |

### Tests

- Test bonus naming: functional name vs “high perceived value” name (same bonus).
- Test stack order: objection-first bonuses vs acceleration-first bonuses.
- Test value anchoring sequence: alternatives/cost-of-inaction before price vs after.
- Test proof placement: proof before mechanism vs after mechanism.
- Test CTA timing: earlier button reveal vs later (keep script constant).
