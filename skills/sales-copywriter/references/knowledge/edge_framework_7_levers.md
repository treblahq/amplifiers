# Edge Framework (Dopamine Copy + 7 Levers)

> **Objective:** Build scalable direct-response creatives by packaging a sharp Edge (angle) and delivering it with dopamine pacing, congruence, and strong closing.

## Notes

- Quality beats volume: fewer creatives with sharper edges outperform spammy variation dumps.
- Treat comments and audience feedback as saturation signals, not as "engagement" to chase.

## Overview

This document is a focused playbook on **Edge Framework (Dopamine Copy + 7 Levers)**.

Primary job: build scalable direct-response creatives by packaging a sharp Edge (angle) and delivering it with dopamine pacing, congruence, and strong closing.

- Focus: generate pattern interrupts that win attention *fast*, then earn belief with proof.
- Focus: reduce friction, increase trust, and keep message-match from ad → page → decision.

## Key concepts

- Edge (angle packaging) vs hook (opening) — don’t confuse them
- Two sourcing modes: organic modeling and paid modeling (validated ads)
- 7 levers to beat control: format/avatar, hook, landing line, congruence, context, dopamine shots, closing
- Dopamine copy: short sentences, minimal connectors, pattern interrupts
- Landing line (post-hook): open a loop and lock attention
- Congruence: avatar + language + proof + visuals must match
- Context: make the story specific and real (not generic pain)
- Closing: post-CTA bullets + a real reason why + a strong last line
- Testing: isolate variables, document learnings, build winner families

## Execution framework

1. **Build your research feed (organic + paid) where your avatar actually spends time**
   - Intent: Create your research feed (organic + paid) where your avatar actually spends time in a minimum viable form; ship version 1 fast and iterate based on data.
   - Output: A minimum viable version of your research feed (organic + paid) where your avatar actually spends time you can ship this week, with clear acceptance criteria.
   - Pitfall: Over-building before validation — you spend time, then discover the bottleneck was upstream.
2. **Pick an edge (angle) and define the promise + mechanism + proof constraint**
   - Intent: Pick one persuasion thesis (driver + promise + mechanism) with a clear proof constraint so the creative can be executed and tested.
   - Output: An edge brief: driver, promise, mechanism, proof constraint, and the single CTA.
   - Pitfall: Picking an edge you can’t prove (or mixing multiple edges), so the creative can’t build belief.
3. **Choose a production package (format + avatar + music/redline) that fits the edge**
   - Intent: Choose the production package (format, avatar, setting, music/redline) so it matches the edge and feels believable.
   - Output: A production brief: format, avatar, setting, proof visuals, music/redline, and filming/editing notes.
   - Pitfall: Choosing a format/avatar that breaks congruence (it feels fake), so belief drops even if the hook gets attention.
4. **Write the hook (visual + written/spoken) and the landing line (post-hook loop)**
   - Intent: Write the post-hook landing line to open a loop and lock attention (strong enough to be a hook, but positioned after it).
   - Output: A hook + landing-line set: 10 hook options + 5 landing lines, each mapped to one proof asset.
   - Pitfall: A landing line that doesn’t open a loop (it reads like filler), so attention drops right after the hook.
5. **Write the body with context + proof, using dopamine shots to maintain pacing**
   - Intent: Write the body with specific context and proof, inserting dopamine shots (connector-free interrupts) to reset attention.
   - Output: A full ad script: hook → landing line → body (context + proof + dopamine shots) → CTA.
   - Pitfall: Over-explaining with connectors and long sentences — pacing dies and watch time collapses.
6. **Close with a post-CTA (bullets + reason why) and a strong last line**
   - Intent: Close with a post-CTA (bullets + reason why) and a strong last line so the not-yet-convinced segment clicks.
   - Output: A closing block: CTA line + 3 bullets + 1 reason-why + last-line variant (humanized authority or push–pull).
   - Pitfall: A weak close (generic bullets / no reason why / no strong last line), so the not-yet-convinced segment never clicks.
7. **Test with control, scale winners as families, and refresh when saturation signals appear**
   - Intent: Define the hypothesis, variants, window, and decision criteria before running it.
   - Output: A saturation monitor: frequency thresholds, creative refresh plan, and brand-risk guardrails.
   - Pitfall: Ignoring frequency/saturation — CPM rises, CPA spikes, and the account gets unstable.

## EDGE framework reference (what to build, what to change, what to test)

This section turns the Edge approach into an execution-ready checklist for ad creatives (especially short-form video ads). It is designed to help you **create**, **model**, and **beat control** without spamming low-quality variations.

### What "Edge" means (practical definition)

- **Edge = angle packaging.** You can sell the same underlying promise by "packaging" it in different angles (fear vs desire, conspiracy, GC/story, medical authority, etc.).
- **Edge is not a hook.** Hook = the opening. Edge = the persuasion thesis that makes the hook believable and the rest of the ad coherent.
- **Edge can sell but not scale.** A sharp edge might convert for a narrow pocket of traffic but fatigue fast; scalable edges usually have stronger proof + broader congruence.

### Two sourcing modes (how to get ideas without inventing from scratch)

- **Mode A — Organic modeling:** find a viral organic video your avatar actually watches; keep the structure; swap the core details; then add paid elements (proof, promise clarity, CTA).
- **Mode B — Paid modeling ("validated" ads):** pick an ad already scaling; don’t copy/paste; "beat control" by changing specific levers so the new ad is meaningfully different and more competitive in auction.

```text
Organic → Paid adaptation (workflow)
1) Pick a viral organic video in the niche (or adjacent interests of the avatar)
2) Replicate the hook structure as faithfully as possible
3) Replicate the body structure, swapping specifics to match your product/mechanism
4) Add: promise clarity + proof + authority + ONE CTA
5) Add: landing line (post-hook) + dopamine shots (pacing)
```

### The 7 levers to "beat control" (make a better version of a validated ad)

| Lever | What you change | Why it matters | Fast way to execute |
|---|---|---|---|
| 1) Format + avatar | UGC vs doctor vs podcast cut vs demo; who is speaking | First 5 seconds decide if you even get listened to | Swap to the next most-validated format in the niche; or replace the avatar with a different person that triggers the same psychological function |
| 2) Visual + written hook | What is shown + first on-screen / spoken line | Stops the scroll; sets the promise tension | Make the visual prove or create curiosity about what the copy claims (don’t rely on unrelated "generic" scroll-stoppers) |
| 3) Landing line (post-hook) | The 1 sentence right after the hook | Opens a loop and locks attention | Write a line so strong it *could* be the hook; keep it curious/controversial and specific |
| 4) Congruence | Consistency between avatar, language, proof, visuals | Incongruence kills belief instantly | Ask: "Would THIS person really say THIS? Would THIS proof exist in THIS context?" |
| 5) Avatar context | Specificity of the story/world | Makes it feel real, not generic | Expand with real-life constraints (age, situation, routines, consequences) and niche-native references |
| 6) Dopamine shots | Micro pattern interrupts inside the body | Prevents drop-off; resets attention | Insert short, connector-free lines that cut the rhythm (not logically "bridged") |
| 7) Closing | Post-CTA bullets + reason why + last line | Converts the "not yet convinced" segment | Add a post-CTA: bullets + reason why; end with "humanized authority" or push–pull |

### Dopamine copy rules (pacing that holds attention)

- Cut connectors: reduce "because / therefore / then / so" chains; prefer short, standalone sentences.
- Use "dopamine shots": lines that interrupt the narrative rhythm to re-capture attention.
- Avoid over-explaining the mechanism in the ad; earn the click, then expand on the VSL/page.
- Keep claims "dangerous" (high curiosity) without lying; proof must be attachable.

```text
Connector cut (rewrite pattern)
Before: "Because X, you should do Y so that Z happens."
After:  "You don’t need X."
        "You need Y."
        "Do this once."
        "Watch what happens."
```

### Landing line (post-hook) templates

Landing line = the sentence right after the hook. Job: open a loop so the viewer *stays*.

```text
Landing line (templates)
- "Don’t test this more than once a day." (implies power + risk)
- "This is exactly what I’d do to go from {BAD_STATE} to {GOOD_STATE} in {TIME}." (implies plan)
- "If you’re doing {COMMON_BEHAVIOR}, you’re making it worse." (contrarian)
- "They’ll try to take this down." (conspiracy/forbidden)
```

### Congruence checklist (fast QA)

- Avatar-language match: vocabulary, intensity, and references fit the person on screen.
- Proof-context match: the proof shown is plausible for that avatar and setting (no "medical-data dump" from a casual UGC creator).
- Visual-copy match: what you show supports what you claim (proof/curiosity), not random attention bait.
- Outcome match: the promise aligns with what the mechanism can plausibly deliver.

### Closing structure (post-CTA + last line)

```text
Post-CTA (20 seconds max)
CTA: "Tap Learn More" / "Watch now" / "Get the recipe" (ONE clear action)

Bullets (promise of content):
- "In the video you’ll discover {SPECIFIC THING #1}."
- "You’ll see {SPECIFIC THING #2}."
- "And why {COMMON HABIT} might be sabotaging you." 

Reason why (make it make sense):
- "This used to be paid." + "Here’s why it’s free today." (tie to a real reason)

Last line option A — Humanized authority:
- "I’m telling you: this works. Test it once. Then come back and thank me." 

Last line option B — Push–pull:
- "If you want it, click. If you don’t, that’s fine." (creates choice power)
```

### Testing + scaling (winner families)

- Test edges with control: keep format + CTA stable while swapping the edge (angle packaging).
- Scale winners as families: new openings + proof variants + avatars (same thesis).
- Use comments as a saturation signal: when the audience complains they "can’t stand seeing this anymore", refresh the production package (avatar/mode/visual proof), not just the wording.

## Common mistakes

- Confusing *hook* (opening line) with *angle* (persuasion thesis).
- Writing hooks that don’t imply a promise or tension (they read like facts).
- Not pairing hooks with proof assets (so CTR is driven by hype, not belief).
- Saving hooks without tags (driver, stage, avatar, proof type) — the library becomes unusable.
- Long sentences with connectors (“because”, “therefore”) that kill rhythm.
- Opening loops you never close (you lose trust).
- Trying to “sound smart” instead of being sharp and specific.
- Replacing proof with adjectives (“insane”, “revolutionary”).
- Testing without a hypothesis (you can’t learn).
- Scaling budget before you have creative replenishment (frequency spikes).

## Tests and measurement

### Metrics

| Metric | What it indicates | How to use |
|---|---|---|
| 3s hold / Thumbstop | Opening strength | Iterate hook category + first frame; keep it 1 line. |
| CTR | Hook + promise match | Test angles/promise specificity; pair with proof. |
| CPA/CAC | Edge × funnel efficiency | Fix the bottleneck before scaling; compare edges on CPA, not vibes. |
| Avg watch time | Rhythm and payoff | Cut connectors; close loops; tighten pacing. |
| Page CVR | Sales-stage conversion | Improve proof placement, readability, and offer clarity. |
| Scroll depth | Argument flow | Reorder sections; add subhead clarity; remove friction. |

### Tests

- Test edge A vs edge B with the same format (same length, same CTA) to isolate the angle.
- Test “sells” vs “scales”: keep a selling edge as a control while testing scalable variants (audiences/placements).
- Test 5 hook categories on the same angle (keep offer constant).
- Test promise specificity: vague vs specific (number/timeframe/criteria).
- Test proof-first vs promise-first openings (especially on warm traffic).
- Rewrite the same message with 50% fewer connectors; compare watch time and CTR.
- Test open-loop vs closed-loop hooks (curiosity vs clarity).
- Test proof placement: proof before mechanism vs after mechanism.
