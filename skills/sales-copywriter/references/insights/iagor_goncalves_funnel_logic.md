# Iagor Gonçalves — Lean Funnel Logic

> **Objective:** Build funnels with a simple, direct, conversion-driven structure (without unnecessary complexity).

## Overview

This document is a focused playbook on **Iagor Gonçalves — Lean Funnel Logic**.

Primary job: build funnels with a simple, direct, conversion-driven structure (without unnecessary complexity).

- Focus: packaging and framing — the offer is the conversion engine (not the page design).
- Focus: reduce friction, increase trust, and keep message-match from ad → page → decision.

## Key concepts

- Funnel as a minimum viable sequence
- Clarity and speed of execution
- A strong offer as the funnel’s axis
- How to use pre-sell and VSL without excess
- Optimization by bottleneck
- How to operate perpetual with discipline

## Execution framework

1. **Define offer and promise (1 line)**
   - Intent: Write the transformation in one line (before → after), with specificity.
   - Output: One sentence promise + a one-line offer description (who it’s for, what changes, and what happens next).
   - Pitfall: A vague or multi-claim promise — you lose clarity, create skepticism, and reduce conversion.
2. **Build a bridge for cold traffic (if needed)**
   - Intent: Define campaign strategy, creatives, and measurement by stage (TOFU/MOFU/BOFU).
   - Output: A minimum viable version of a bridge for cold traffic (if needed) you can ship this week, with clear acceptance criteria.
   - Pitfall: Over-building before validation — you spend time, then discover the bottleneck was upstream.
3. **Create an objective sales page (VSL or long-form)**
   - Intent: Structure the visual path (fold-by-fold) to reduce friction and build trust.
   - Output: A minimum viable version of an objective sales page (VSL or long-form) you can ship this week, with clear acceptance criteria.
   - Pitfall: Over-building before validation — you spend time, then discover the bottleneck was upstream.
4. **Optimize checkout and reduce friction**
   - Intent: Run short cycles: analyze → pick the bottleneck → test → consolidate learnings.
   - Output: A friction audit + prioritized fixes (UX, copy, clarity, policies) with expected impact.
   - Pitfall: Removing friction in the wrong place (or adding new friction) — you lower trust while trying to raise CVR.
5. **Add basic AOV (bump/upsell) if it makes sense**
   - Intent: Improve AOV/LTV with coherent expansion (bump/upsell/backend) so you can sustain higher CAC safely.
   - Output: An AOV/LTV improvement plan: bump/upsell/cross-sell/backend actions and tracking events.
   - Pitfall: Trying to raise AOV/LTV with unrelated add-ons — short-term revenue, long-term trust loss.
6. **Build a minimum backend (recovery email)**
   - Intent: Create a sequence with one goal per email + trigger + single primary CTA.
   - Output: A sequence map (entry/exit event, email-by-email angles, CTAs, and triggers).
   - Pitfall: Multiple CTAs per email and “newsletter vibes” with no single objective.
7. **Optimize by stage weekly**
   - Intent: Run short cycles: analyze → pick the bottleneck → test → consolidate learnings.
   - Output: A weekly loop: bottleneck → test → learnings → consolidation.
   - Pitfall: Optimizing too many stages at once — you can’t isolate what improved and you break message-match.

## Lean funnel reference (minimum viable sequence)

Use this as a default when you want speed, clarity, and clean learning.

### Minimum viable funnel (template)

```text
1) Creative (hook + proof) → one CTA
2) Bridge (optional): pre-sell/lead magnet if cold traffic needs belief
3) Sales asset: VSL or long-form page (mechanism + proof + offer)
4) Checkout: friction removal + trust + clear terms
5) Backend: recovery email + onboarding quick win
Optional: bump/upsell only if complementary and coherent
```

### Complexity test (decision rule)

- If you need complexity to sell, the offer/promise/mechanism is weak.
- Add one element at a time (pre-sell, VSL, quiz) only when the bottleneck demands it.
- Optimize by stage weekly: one bottleneck, one variable, one learning.

## Common mistakes

- An aggressive promise without a mechanism (refund magnet).
- Fake urgency/scarcity (short-term CVR, long-term brand damage).
- Bonuses that compete with the core (decision friction).
- Price revealed before value is anchored (sticker shock).
- Optimizing visuals while ignoring payment friction (methods, approval rate).
- Bumps/upsells that feel unrelated (low take rate and trust loss).
- Overloading the checkout with copy (more reading = more doubt).
- Testing without a hypothesis (you can’t learn).
- Scaling budget before you have creative replenishment (frequency spikes).
- Changing audience + creative + offer at once (no attribution).

## Tests and measurement

### Metrics

| Metric | What it indicates | How to use |
|---|---|---|
| 25%/50% watch rate | Retention | Tighten the first 60s; reduce fluff; strengthen proof cadence. |
| CTA click rate | Pitch clarity | Align CTA to promise; place the button at the pitch moment. |

### Tests

- Test bonus naming: functional name vs “high perceived value” name (same bonus).
- Test stack order: objection-first bonuses vs acceleration-first bonuses.
- Test value anchoring sequence: alternatives/cost-of-inaction before price vs after.
- Test proof placement: proof before mechanism vs after mechanism.
- Test CTA timing: earlier button reveal vs later (keep script constant).
