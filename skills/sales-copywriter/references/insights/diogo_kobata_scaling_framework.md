## Execution framework

1. **Define CAC ceiling and unit economics**
   - Intent: Define constraints, success criteria, and ROI thresholds before building; make the trade-offs explicit.
   - Output: A baseline report + CAC ceiling (with guardrails) and how to calculate breakeven targets.
   - Pitfall: No baseline/CAC ceiling — scaling becomes emotional and unit economics get ignored.
2. **Separate testing and scaling campaigns**
   - Intent: Define the hypothesis, variants, window, and decision criteria before running it.
   - Output: A test brief: hypothesis, variants, audience, window, and decision rule.
   - Pitfall: Changing multiple variables and calling it a test (no learning).
3. **Run creative tests with hypotheses**
   - Intent: Define the hypothesis, variants, window, and decision criteria before running it.
   - Output: A test brief: hypothesis, variants, audience, window, and decision rule.
   - Pitfall: Changing multiple variables and calling it a test (no learning).
4. **Scale winners horizontally first**
   - Intent: Turn winners into a family: new openings, proof variants, and formats while keeping the same thesis.
   - Output: A variation map: new openings + proof variants + formats, all anchored to the same thesis.
   - Pitfall: Scaling without creative replenishment (frequency spikes, performance drops).
5. **Scale vertically with control**
   - Intent: Turn winners into a family: new openings, proof variants, and formats while keeping the same thesis.
   - Output: A variation map: new openings + proof variants + formats, all anchored to the same thesis.
   - Pitfall: Scaling without creative replenishment (frequency spikes, performance drops).
6. **Refresh creatives to avoid saturation**
   - Intent: Monitor saturation and protect the account: refresh creatives, manage frequency, and avoid fatigue-driven volatility.
   - Output: A saturation monitor: frequency thresholds, creative refresh plan, and brand-risk guardrails.
   - Pitfall: Ignoring frequency/saturation — CPM rises, CPA spikes, and the account gets unstable.
7. **Document learning and standardize**
   - Intent: Document what happened (hypothesis → result → decision) and update the system so the next cycle is faster.
   - Output: A learning log: hypothesis, result, decision, and next action (plus an updated playbook/library entry).
   - Pitfall: Not writing down what worked (and why) — you repeat tests, lose context, and scale randomness.

## Scaling reference (process > vibes)

This section is a disciplined scaling OS: structure, rules, and risk controls.

### Account structure (testing vs scaling)

- Testing campaigns: many creatives, controlled budgets, clean learning windows.
- Scaling campaigns: only proven winners, controlled ramps, strict guardrails.
- Naming conventions: make reporting obvious (angle, format, stage, date).

### Scaling rules (simple)

```text
1) Validate stability over a window (not one good day)
2) Scale horizontally first (new audiences/placements)
3) Scale vertically with caps (budget ramps)
4) Refresh creatives before frequency spikes
5) Protect the account (policy + feedback + brand risk)
```

### Creative replenishment (winner families)

- One winner → build a family: new hooks, proof variants, formats, and CTAs (same thesis).
- Track fatigue signals: frequency, CPM rises, CTR decay, comment tone.
- Maintain a weekly production quota so scaling doesn’t stall.

## Common mistakes

- An aggressive promise without a mechanism (refund magnet).
- Fake urgency/scarcity (short-term CVR, long-term brand damage).
- Bonuses that compete with the core (decision friction).
- Price revealed before value is anchored (sticker shock).
- Testing without a hypothesis (you can’t learn).
- Scaling budget before you have creative replenishment (frequency spikes).
- Changing audience + creative + offer at once (no attribution).

## Tests and measurement

### Metrics

| Metric | What it indicates | How to use |
|---|---|---|
| CPA/CAC | Acquisition efficiency | Optimize by bottleneck; don’t scale what’s not stable. |
| Frequency | Saturation | Replenish creatives; expand audiences; control budget ramps. |

### Tests

- Test bonus naming: functional name vs “high perceived value” name (same bonus).
- Test stack order: objection-first bonuses vs acceleration-first bonuses.
- Test value anchoring sequence: alternatives/cost-of-inaction before price vs after.
- Test one variable at a time (angle OR hook OR proof) for clean learning.
- Scale horizontally first (new audiences) before vertical budget increases.
