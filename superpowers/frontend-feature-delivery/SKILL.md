# Frontend Feature Delivery

## Mandate

Ship frontend features that are structurally sound, visually clear, readable in
the UI, and documented well enough for the next contributor.

## When to Use

- Building a new screen, flow, or interaction in a React stack
- Refactoring a feature that suffers from both UX and architecture issues
- Delivering product-facing UI work that needs code, copy, and documentation

---

## Workflow

1. Diagnose the product goal, target user action, and constraints
2. Define hierarchy, layout logic, and the primary path through the interface
3. Implement the feature with clear React boundaries and reusable patterns
4. Rewrite UI strings that feel vague, robotic, or inconsistent
5. Update the minimal documentation required by the change

---

## Input Checklist

Before starting, collect:

1. Feature goal and acceptance criteria
2. Target user and primary action
3. Existing UI or design constraints
4. Technical constraints in the current React codebase

---

## Output Standard

Deliver where possible:

1. Screen or flow logic
2. Component and hook boundaries
3. Notes on hierarchy, spacing, or interaction emphasis
4. Polished UI copy and key state text
5. Minimal documentation updates when system behavior changes

---

## Composition Rules

- Use product design to define the structure before code details
- Use React architecture to keep implementation modular and testable
- Use humanized writing for UI labels, helper text, and state messages
- Use knowledge writing only for factual updates tied to the feature
