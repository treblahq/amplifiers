# Repository documentation delivery

> Turn a repository into a cleaner open-source surface with stronger README, contribution docs, writing rules, and navigable structure.

This superpower is for repository-level documentation work. It combines factual
documentation, natural writing, GitHub-friendly structure, and lightweight
presentation thinking for surfaces such as `README.md`, `CONTRIBUTING.md`, and
project standards.

## Use when

- Writing or restructuring a project `README.md`
- Adding contribution guides, writing standards, or documentation indexes
- Improving the first impression of an open-source repository
- Making repository docs easier to scan for both humans and AI tools

## Workflow

1. Inspect the repository and identify the missing or weak documentation surfaces
2. Define the information hierarchy across `README.md`, standards, and support docs
3. Write factual documentation with clear navigation and minimal duplication
4. Improve tone, headings, and wording so the text sounds natural and direct
5. Use GitHub-friendly HTML or markdown structure when visual control matters

## Output standard

- A clearer documentation hierarchy
- Improved repository entry points such as `README.md`
- Supporting docs with cleaner scope and structure
- Better first-impression presentation without introducing visual clutter
