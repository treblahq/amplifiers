# High-Converting Angles

> **Objective:** Build a catalog of angles that generate clicks and purchases, with an adaptation guide.

## Notes

- This document includes an extra section with an angle catalog and examples.

## Overview

This document is a focused playbook on **High-Converting Angles**.

Primary job: build a catalog of angles that generate clicks and purchases, with an adaptation guide.

- Focus: generate pattern interrupts that win attention *fast*, then earn belief with proof.

## Key concepts

- What an angle is (and how it differs from a hook)
- Angles by driver (loss, gain, status, safety)
- How to pair angle + proof
- How to generate variations without losing clarity
- How to choose angles by funnel stage
- How to document winners

## Execution framework

1. **Choose the primary psychological driver**
   - Intent: Choose the primary psychological driver based on constraints (stage, proof, capacity) and commit for a test window.
   - Output: A decision doc for the primary psychological driver with rationale, constraints, and a test plan.
   - Pitfall: Choosing based on personal taste (not constraints/proof) — you lock into a weak direction.
2. **Pick 5 candidate angles**
   - Intent: Pick one persuasion thesis (driver + promise + proof) and keep it consistent across the asset.
   - Output: 1–3 angles (theses) with: driver → promise → mechanism → proof → CTA.
   - Pitfall: Mixing multiple angles in the same asset (no single persuasion thesis).
3. **Generate 5 hooks per angle**
   - Intent: Write a one-line pattern interrupt that creates tension/curiosity; generate variations and test.
   - Output: 10–25 hook lines, tagged by driver/angle, each with 1 suggested proof asset.
   - Pitfall: Writing “clever” lines without a clear promise, audience, or proof.
4. **Add mechanism/proof per angle**
   - Intent: Collect real proof (screenshots, numbers, demos) and place it with context.
   - Output: A proof pack: 3–10 assets (screenshots, numbers, demos) mapped to key claims.
   - Pitfall: Using proof with no context (no baseline, timeframe, or attribution).
5. **Test in creatives (hypotheses)**
   - Intent: Define the hypothesis, variants, window, and decision criteria before running it.
   - Output: A test brief: hypothesis, variants, audience, window, and decision rule.
   - Pitfall: Changing multiple variables and calling it a test (no learning).
6. **Push winners into landing and email**
   - Intent: Turn winners into a family: new openings, proof variants, and formats while keeping the same thesis.
   - Output: A variation map: new openings + proof variants + formats, all anchored to the same thesis.
   - Pitfall: Scaling without creative replenishment (frequency spikes, performance drops).
7. **Save the library by category**
   - Intent: Save winners in a tagged library (angle, driver, stage, proof) so you can reuse and build families fast.
   - Output: A tagged library entry: category, driver, stage, proof, and performance notes.
   - Pitfall: Saving without tags/metadata (angle, stage, proof) — the library becomes a junk drawer.

## Angle catalog (for testing)

Angle = persuasion thesis. Hook = opening line. Don’t confuse them.

### Safety / Certainty

- Risk reduction (guarantee, step-by-step, predictability)
- Avoid a costly mistake (the “hidden cost” of the problem)
- A simple, repeatable system (control)

### Speed / Time

- A legitimate shortcut (without skipping fundamentals)
- Less effort (templates, automation, checklists)
- Results in a timeframe (when real)

### Status / Identity

- Be seen as [identity] (standards, method, discipline)
- Top 1% (behaviors and decisions)
- Professional vs amateur (contrast)

### Loss / Urgency

- What you lose if you don’t act (money, time, opportunity)
- A real window (timing) (event, calendar, capacity)
- Saturation/competition (when applicable)

### Turning an angle into a hook (example)

```text
Angle: avoid a costly mistake
Hook: “If you do this, you’re losing money without realizing it.”
Mechanism: “The problem is [cause], not [symptom].”
Proof: “Look at this example…”
CTA: “See the step-by-step.”
```

## Common mistakes

- Confusing *hook* (opening line) with *angle* (persuasion thesis).
- Writing hooks that don’t imply a promise or tension (they read like facts).
- Not pairing hooks with proof assets (so CTR is driven by hype, not belief).
- Saving hooks without tags (driver, stage, avatar, proof type) — the library becomes unusable.

## Tests and measurement

### Metrics

| Metric | What it indicates | How to use |
|---|---|---|
| 3s hold / Thumbstop | Opening strength | Iterate hook category + first frame; keep it 1 line. |
| CTR | Hook + promise match | Test angles/promise specificity; pair with proof. |
| CPA/CAC | Edge × funnel efficiency | Fix the bottleneck before scaling; compare edges on CPA, not vibes. |

### Tests

- Test edge A vs edge B with the same format (same length, same CTA) to isolate the angle.
- Test “sells” vs “scales”: keep a selling edge as a control while testing scalable variants (audiences/placements).
- Test 5 hook categories on the same angle (keep offer constant).
- Test promise specificity: vague vs specific (number/timeframe/criteria).
- Test proof-first vs promise-first openings (especially on warm traffic).
