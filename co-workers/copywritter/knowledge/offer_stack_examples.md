## Overview

This document is a focused playbook on **Offer Stack Examples**.

Primary job: use stack examples by product type to accelerate offer building and bonuses.

- Focus: packaging and framing — the offer is the conversion engine (not the page design).

## Key concepts

- Stacks for low, mid, and high ticket
- How to give each bonus a function
- Guarantee examples by context
- How to use fast-action bonuses with integrity
- How to avoid bloated, unrealistic stacks
- How to connect the stack to the mechanism

## Execution framework

1. **Define the core transformation**
   - Intent: Write the transformation in one line (before → after), with specificity.
   - Output: A 1-page definition of the core transformation with scope, criteria, and constraints.
   - Pitfall: Defining it vaguely (no scope, criteria, or constraints) — execution becomes random and untestable.
2. **List the 3 main objections**
   - Intent: List the top objections and map each to a fix (proof, stack item, guarantee, clarification) so the asset pre-empts doubt.
   - Output: An objection map (top 10) → one fix per objection (proof, bonus, guarantee, clarification).
   - Pitfall: Inventing bonuses/claims without mapping objections (the asset never resolves doubt).
3. **Create bonuses with a function for each objection**
   - Intent: List the top objections and map each to a fix (proof, stack item, guarantee, clarification) so the asset pre-empts doubt.
   - Output: An objection map (top 10) → one fix per objection (proof, bonus, guarantee, clarification).
   - Pitfall: Inventing bonuses/claims without mapping objections (the asset never resolves doubt).
4. **Choose a coherent guarantee**
   - Intent: Reduce risk and objections with a clear guarantee, scope, and realistic expectations.
   - Output: A guarantee statement with criteria, scope, and expectation alignment.
   - Pitfall: A vague or overly broad guarantee — it increases refunds and attracts the wrong buyers.
5. **Create realistic value anchoring**
   - Intent: Anchor value before revealing price: stack, proof, alternatives, and cost of inaction — then frame price as an investment.
   - Output: A value-anchoring sequence: alternatives + cost of inaction + proof → price reveal.
   - Pitfall: Revealing price before value is anchored — sticker shock and low conversion.
6. **Test the stack (A/B variations)**
   - Intent: Define the hypothesis, variants, window, and decision criteria before running it.
   - Output: A test brief: hypothesis, variants, audience, window, and decision rule.
   - Pitfall: Changing multiple variables and calling it a test (no learning).
7. **Measure impact on CVR/AOV/refunds**
   - Intent: Improve AOV/LTV with coherent expansion (bump/upsell/backend) so you can sustain higher CAC safely.
   - Output: An AOV/LTV improvement plan: bump/upsell/cross-sell/backend actions and tracking events.
   - Pitfall: Trying to raise AOV/LTV with unrelated add-ons — short-term revenue, long-term trust loss.

## Stack examples (to adapt)

Use as a functional reference. Adjust to your mechanism and proof level.

### Low ticket (entry)

- Core: quick win (1 fast outcome)
- Bonus: ready-to-use templates
- Bonus: anti-mistake checklist
- Guarantee: short and simple

### Low ticket (format-first utility)

- Core: delivery format + cadence (what arrives, when, where)
- Bonus: pinned index / quickstart (so they can use it immediately)
- Bonus: tagged library (prompts/swipes/checklists) for fast retrieval
- Guarantee: simple and scoped (sets expectations)

### Mid ticket (core)

- Core: complete method (5–7 steps)
- Bonus: acceleration (7-day plan)
- Bonus: execution (template library)
- Bonus: basic support (Q&A/light review)
- Guarantee: coherent risk reversal

### High ticket (implementation)

- Core: guided execution (DWY/DFY) — speed + accountability
- Bonus: reviews and audits
- Bonus: templates + SOPs
- Bonus: priority support
- Guarantee: milestone-based (when applicable)

### High ticket (done-for-you / time buying)

- Core: implementation (team executes with you / for you)
- Bonus: operations + content production (when coherent with the promise)
- Bonus: dashboards + weekly reporting (visibility and control)
- Bonus: SOPs and handoff (so results persist)
- Guarantee: milestone-based (or scope-based) to prevent misalignment

### SaaS (subscription)

- Core: product + onboarding
- Bonus: templates (fast setup)
- Bonus: playbooks (use cases)
- Bonus: concierge/CS (for higher plans)
- Guarantee: trial or testing period

## Common mistakes

- An aggressive promise without a mechanism (refund magnet).
- Fake urgency/scarcity (short-term CVR, long-term brand damage).
- Bonuses that compete with the core (decision friction).
- Price revealed before value is anchored (sticker shock).

## Tests and measurement

### Tests

- Test bonus naming: functional name vs “high perceived value” name (same bonus).
- Test stack order: objection-first bonuses vs acceleration-first bonuses.
- Test value anchoring sequence: alternatives/cost-of-inaction before price vs after.
