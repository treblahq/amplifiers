# Headline Formulas

> **Objective:** Generate fast, testable headlines by formula, with placeholders to adapt to your mechanism and proof.

## Notes

- This document includes an extra section with dozens of formulas and generated variations.

## Overview

This document is a focused playbook on **Headline Formulas**.

Primary job: generate fast, testable headlines by formula, with placeholders to adapt to your mechanism and proof.

- Focus: generate pattern interrupts that win attention *fast*, then earn belief with proof.

## Key concepts

- Formulas by driver (curiosity, proof, warning, contrarian)
- How to change the promise without changing the mechanism
- How to add specificity (timeframe, number, criteria)
- How to avoid generic headlines
- How to create 20 variations per angle
- How to use across ads, landers, and emails

## Execution framework

1. **Choose 1 central promise and 1 audience segment**
   - Intent: Define a single segment with pain, context, and language.
   - Output: An ICP one-pager: segment, context, pains, language, buying triggers, and disqualifiers.
   - Pitfall: Targeting everyone (or writing a generic persona) — the copy can’t be specific, so conversion drops.
2. **Pick 2–3 headline formulas**
   - Intent: Generate headline variants with specificity (timeframe/number/criteria) and map proof to each claim.
   - Output: 15–30 headline variants with specificity (number/timeframe/criteria) + proof notes.
   - Pitfall: Writing “clever” lines without a clear promise, audience, or proof.
3. **Generate 10–20 variations with specificity**
   - Intent: Turn winners into a family: new openings, proof variants, and formats while keeping the same thesis.
   - Output: A variation map: new openings + proof variants + formats, all anchored to the same thesis.
   - Pitfall: Generating “variations” that are just synonyms — no new angle, no new learning.
4. **Select the 5 clearest and strongest**
   - Intent: Score candidates by clarity, specificity, and proof-ability; keep only the top 3–5 so execution stays focused.
   - Output: A scored shortlist of the top 3–5 candidates with notes on proof, risk, and stage.
   - Pitfall: Picking based on taste instead of clarity, specificity, and proof constraints.
5. **Add 1 suggested proof element per headline**
   - Intent: Collect real proof (screenshots, numbers, demos) and place it with context.
   - Output: A proof pack: 3–10 assets (screenshots, numbers, demos) mapped to key claims.
   - Pitfall: Using proof with no context (no baseline, timeframe, or attribution).
6. **Test in creatives and landing pages**
   - Intent: Define the hypothesis, variants, window, and decision criteria before running it.
   - Output: A test brief: hypothesis, variants, audience, window, and decision rule.
   - Pitfall: Changing multiple variables and calling it a test (no learning).
7. **Save winners by formula and angle**
   - Intent: Turn winners into a family: new openings, proof variants, and formats while keeping the same thesis.
   - Output: A variation map: new openings + proof variants + formats, all anchored to the same thesis.
   - Pitfall: Scaling without creative replenishment (frequency spikes, performance drops).

## Ready-to-use formulas (with placeholders)

Useful placeholders: `{PERSONA}`, `{RESULT}`, `{TIMEFRAME}`, `{MECHANISM}`, `{PROOF}`, `{OBJECTION}`, `{SACRIFICE}`, `{TOPIC}`.

- How {PERSONA} can {RESULT} in {TIMEFRAME} using {MECHANISM} (even if {OBJECTION}).
- How exactly {PERSONA} can {RESULT} in {TIMEFRAME} using {MECHANISM} (even if {OBJECTION}).
- {NUMBER} mistakes that make you {PAIN} — and how to fix them in {TIMEFRAME}.
- The fastest way to {RESULT} without {SACRIFICE}.
- The quickest way to {RESULT} without {SACRIFICE}.
- You don’t need {THING}. You need {MECHANISM}.
- What nobody tells you about {TOPIC} (and why it changes everything).
- If you’re {SITUATION}, do this before {ACTION}.
- The simple guide to {RESULT} (without {SACRIFICE}).
- A simple guide to {RESULT} (without {SACRIFICE}).
- Stop {MISTAKE}. Start {NEW_ACTION}.
- Quit {MISTAKE}. Start {NEW_ACTION}.
- The uncomfortable truth about {TOPIC}: {THESIS}.
- The {MECHANISM} method for {RESULT}: step by step.

### Headline checklist (anti-generic)

- Is there a clear audience (even if implicit)?
- Does the promise include a criterion (timeframe, number, condition)?
- Is the mechanism present (why it works)?
- Does it avoid empty adjectives (“amazing”, “revolutionary”)?
- Does it sound simple when read out loud?

## Tests and measurement

### Metrics

| Metric | What it indicates | How to use |
|---|---|---|
| 3s hold / Thumbstop | Opening strength | Iterate hook category + first frame; keep it 1 line. |
| CTR | Hook + promise match | Test angles/promise specificity; pair with proof. |
| CPA/CAC | Edge × funnel efficiency | Fix the bottleneck before scaling; compare edges on CPA, not vibes. |

### Tests

- Test edge A vs edge B with the same format (same length, same CTA) to isolate the angle.
- Test “sells” vs “scales”: keep a selling edge as a control while testing scalable variants (audiences/placements).
- Test 5 hook categories on the same angle (keep offer constant).
- Test promise specificity: vague vs specific (number/timeframe/criteria).
- Test proof-first vs promise-first openings (especially on warm traffic).
