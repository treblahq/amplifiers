# Russell Brunson — Core Frameworks

> **Objective:** Apply Value Ladder, Hook-Story-Offer, and Attractive Character to funnels and messaging with consistency.

## Overview

This document is a focused playbook on **Russell Brunson — Core Frameworks**.

Primary job: apply Value Ladder, Hook-Story-Offer, and Attractive Character to funnels and messaging with consistency.

- Focus: generate pattern interrupts that win attention *fast*, then earn belief with proof.
- Focus: packaging and framing — the offer is the conversion engine (not the page design).
- Focus: reduce friction, increase trust, and keep message-match from ad → page → decision.

## Key concepts

- Value Ladder and offer progression
- Hook-Story-Offer (message structure)
- Attractive Character (positioning and voice)
- How to build offers and stacks with narrative
- How to apply HSO in webinars and VSLs
- How to adapt the logic for SaaS and infoproducts

## Execution framework

1. **Define the ladder (steps and progression)**
   - Intent: Map a Value Ladder: each step has a job, a promise, a price band, and a clear next-step trigger.
   - Output: A Value Ladder map: offers by step, price band, promise, and upgrade triggers.
   - Pitfall: No clear progression logic — steps cannibalize each other and upgrades feel pushy.
2. **Create hooks by driver (curiosity/pain/status)**
   - Intent: Write a one-line pattern interrupt that creates tension/curiosity; generate variations and test.
   - Output: 10–25 hook lines, tagged by driver/angle, each with 1 suggested proof asset.
   - Pitfall: Writing “clever” lines without a clear promise, audience, or proof.
3. **Write the story as proof and bridge (no rambling)**
   - Intent: Use story as proof and a bridge: keep it tight, map it to mechanism/proof, and point to the next step.
   - Output: A story bank: 3–5 short stories mapped to objections, proof points, and the CTA.
   - Pitfall: Long stories with no mechanism/proof bridge — people watch/read, but belief and action don’t increase.
4. **Present the offer with stack and risk reversal**
   - Intent: Package the offer: core + bonuses + terms + urgency/scarcity (only if real).
   - Output: An offer stack with function-based bonuses + guarantee + real conditions.
   - Pitfall: A vague or overly broad guarantee — it increases refunds and attracts the wrong buyers.
5. **Tie the funnel sequence together (stages and CTAs)**
   - Intent: Define one next step and phrase it as verb + outcome + what happens next; repeat it at the right moment.
   - Output: A sequence map (entry/exit event, email-by-email angles, CTAs, and triggers).
   - Pitfall: Multiple CTAs per email and “newsletter vibes” with no single objective.
6. **Test hooks and offers separately**
   - Intent: Define the hypothesis, variants, window, and decision criteria before running it.
   - Output: A test brief: hypothesis, variants, audience, window, and decision rule.
   - Pitfall: Changing multiple variables and calling it a test (no learning).
7. **Document winners and replicate**
   - Intent: Document what happened (hypothesis → result → decision) and update the system so the next cycle is faster.
   - Output: A learning log: hypothesis, result, decision, and next action (plus an updated playbook/library entry).
   - Pitfall: Not writing down what worked (and why) — you repeat tests, lose context, and scale randomness.

## Framework reference (Value Ladder, HSO, Attractive Character)

Use this section as a practical reference when adapting the model to your own funnel and offer.

### Value Ladder (how to map offers)

- Each step has a different job: trust → first YES → core transformation → speed/accountability → continuity (LTV).
- Progression must feel *earned*: the next step solves the next bottleneck (not a random add-on).
- The ladder is also a segmentation system: behavior determines which offer is shown next.

```text
Value Ladder map (template)
- Free: [quick win] → qualifies by [signal]
- Entry: [small paid outcome] → proves [mechanism]
- Core: [complete method] → delivers [main transformation]
- High-ticket: [implementation] → buys speed + accountability
- Continuity: [subscription] → maintains results + expansion
Triggers:
- Viewed proof / clicked CTA → show [next step]
- Bought entry → offer core
- Completed onboarding milestone → offer continuity
```

### Hook-Story-Offer (HSO) — portable message structure

- **Hook:** pattern interrupt + tension (one sentence).
- **Story:** why to believe (mechanism + proof + the turning point).
- **Offer:** what to do next (stack + risk reversal + single CTA).

```text
HSO (tight version)
Hook: [contrarian / warning / curiosity]
Story: [what I believed] → [what changed] → [what works now] + [proof]
Offer: [what it is] + [who it's for] + [guarantee] + [CTA]
```

### Attractive Character (AC) — positioning + voice

- **Backstory:** the origin of the mechanism (why you believe it).
- **Parables:** short stories that teach beliefs without lecturing.
- **Character flaws:** human imperfection that makes the message credible.
- **Polarity:** what you stand for/against (filters buyers and increases belief).

```text
AC assets checklist
- 3 parables that support your mechanism
- 3 polarizing beliefs (what you reject in the market)
- 1 origin story (why you built the method)
- 5 proof assets (numbers, cases, demos)
```

### Email application (Soap Opera → Seinfeld style)

- Use a short “sequence” to install belief (origin + mechanism + proof) before pitching hard.
- Then use ongoing emails as parables: one belief, one proof, one CTA.
- Keep the ladder logic: every email should point to the *next logical step* for that segment.

```text
5-email belief sequence (simple)
1) Origin: why I built the mechanism
2) Belief break: myth → truth (what the market gets wrong)
3) Proof: one case + context
4) Objection: time/money/risk (honest answer)
5) Offer bridge: next step + what happens after the click
```

## Common mistakes

- Confusing *hook* (opening line) with *angle* (persuasion thesis).
- Writing hooks that don’t imply a promise or tension (they read like facts).
- Not pairing hooks with proof assets (so CTR is driven by hype, not belief).
- Saving hooks without tags (driver, stage, avatar, proof type) — the library becomes unusable.
- An aggressive promise without a mechanism (refund magnet).
- Fake urgency/scarcity (short-term CVR, long-term brand damage).
- Bonuses that compete with the core (decision friction).
- Price revealed before value is anchored (sticker shock).

## Tests and measurement

### Metrics

| Metric | What it indicates | How to use |
|---|---|---|
| 3s hold / Thumbstop | Opening strength | Iterate hook category + first frame; keep it 1 line. |
| CTR | Hook + promise match | Test angles/promise specificity; pair with proof. |
| 25%/50% watch rate | Retention | Tighten the first 60s; reduce fluff; strengthen proof cadence. |
| CTA click rate | Pitch clarity | Align CTA to promise; place the button at the pitch moment. |
| Activation rate | Time-to-value health | Improve onboarding and quick wins; instrument aha events. |
| Churn | Value continuity | Segment by usage; intervene with education + expansion at the right timing. |
| Upgrade rate | Progression health | Offer the next step based on behavior and readiness; reduce friction. |

### Tests

- Test 5 hook categories on the same angle (keep offer constant).
- Test promise specificity: vague vs specific (number/timeframe/criteria).
- Test proof-first vs promise-first openings (especially on warm traffic).
- Test bonus naming: functional name vs “high perceived value” name (same bonus).
- Test stack order: objection-first bonuses vs acceleration-first bonuses.
- Test value anchoring sequence: alternatives/cost-of-inaction before price vs after.
- Test proof placement: proof before mechanism vs after mechanism.
- Test CTA timing: earlier button reveal vs later (keep script constant).
