# Leandro Ladeira — Emotional Narrative Copy

> **Objective:** Use emotional narrative to create connection, belief, and decision without losing clarity and structure.

## Overview

This document is a focused playbook on **Leandro Ladeira — Emotional Narrative Copy**.

Primary job: use emotional narrative to create connection, belief, and decision without losing clarity and structure.

- Focus: packaging and framing — the offer is the conversion engine (not the page design).
- Focus: reduce friction, increase trust, and keep message-match from ad → page → decision.

## Key concepts

- Story as proof (not entertainment)
- Emotion: identification, desire, relief
- Structure: conflict → turn → mechanism → proof → offer
- How to answer objections inside the narrative
- Voice: human and direct
- How to apply in VSL and sales pages

## Execution framework

1. **Choose a real audience conflict (specific pain)**
   - Intent: Define a single segment with pain, context, and language.
   - Output: An ICP one-pager: segment, context, pains, language, buying triggers, and disqualifiers.
   - Pitfall: Targeting everyone (or writing a generic persona) — the copy can’t be specific, so conversion drops.
2. **Show cost and consequences (no exaggeration)**
   - Intent: Translate the problem into consequences and costs (time, money, status, energy) without exaggeration.
   - Output: A pain map: symptoms → consequences → desired state, plus a language bank.
   - Pitfall: Describing the problem at a surface level (symptoms) without consequences and real context — it doesn’t feel urgent.
3. **Present the turn (mechanism) with clarity**
   - Intent: Explain why it works and why it’s different from the market’s default approach.
   - Output: A 1–3 bullet explanation of *why this works* (and why the default approach fails).
   - Pitfall: Naming a mechanism without explaining how it works in plain language.
4. **Insert proof (cases and results)**
   - Intent: Collect real proof (screenshots, numbers, demos) and place it with context.
   - Output: A proof pack: 3–10 assets (screenshots, numbers, demos) mapped to key claims.
   - Pitfall: Using proof with no context (no baseline, timeframe, or attribution).
5. **Connect the story to the offer and next step**
   - Intent: Use story as proof and a bridge: keep it tight, map it to mechanism/proof, and point to the next step.
   - Output: A story bank: 3–5 short stories mapped to objections, proof points, and the CTA.
   - Pitfall: Long stories with no mechanism/proof bridge — people watch/read, but belief and action don’t increase.
6. **Answer objections throughout (not only in FAQ)**
   - Intent: List the top objections and map each to a fix (proof, stack item, guarantee, clarification) so the asset pre-empts doubt.
   - Output: An objection map (top 10) → one fix per objection (proof, bonus, guarantee, clarification).
   - Pitfall: Inventing bonuses/claims without mapping objections (the asset never resolves doubt).
7. **Edit for rhythm and scanability**
   - Intent: Edit for clarity and scanability: one idea per paragraph, short lines, tight transitions, and proof preserved.
   - Output: An edited draft: shorter paragraphs, clearer headings, preserved proof, and one primary CTA.
   - Pitfall: Over-editing until you remove proof and clarity — the asset reads “clean” but stops converting.

## Emotional narrative reference (storyselling that converts)

Use narrative as proof and a bridge to the decision — not as entertainment.

### Storyselling blueprint (scene-by-scene)

- Identification: “this is me” (specific context, not generic pain).
- Cost: consequences + cost of inaction (no exaggeration).
- Turn: belief break + mechanism reveal (simple).
- Proof: one case or number with context.
- Bridge: what to do next (offer as the logical step).

```text
Story paragraph skeleton
- Context: [real situation]
- Feeling: [emotion]
- Consequence: [what it costs]
- Turn: [new belief + mechanism]
- Proof: [case/number]
- Bridge: [next step + CTA]
```

### Objection weaving (inside the story)

- Time objection → show a small daily action + quick win.
- Money objection → show cost of inaction + why the mechanism is efficient.
- Trust objection → show proof context (baseline/timeframe) + limitation honesty.

### Editing rules (keep the emotion, cut the fluff)

- Short paragraphs (1–2 lines) for scanability.
- One idea per paragraph; remove “because/therefore” chains.
- Proof beats adjectives: keep numbers, screenshots, and concrete examples.

## Common mistakes

- An aggressive promise without a mechanism (refund magnet).
- Fake urgency/scarcity (short-term CVR, long-term brand damage).
- Bonuses that compete with the core (decision friction).
- Price revealed before value is anchored (sticker shock).

## Tests and measurement

### Metrics

| Metric | What it indicates | How to use |
|---|---|---|
| Page CVR | Sales-stage conversion | Improve proof placement, readability, and offer clarity. |
| Scroll depth | Argument flow | Reorder sections; add subhead clarity; remove friction. |
| 25%/50% watch rate | Retention | Tighten the first 60s; reduce fluff; strengthen proof cadence. |
| CTA click rate | Pitch clarity | Align CTA to promise; place the button at the pitch moment. |

### Tests

- Test bonus naming: functional name vs “high perceived value” name (same bonus).
- Test stack order: objection-first bonuses vs acceleration-first bonuses.
- Test value anchoring sequence: alternatives/cost-of-inaction before price vs after.
- Test proof placement: proof before mechanism vs after mechanism.
- Test CTA timing: earlier button reveal vs later (keep script constant).
