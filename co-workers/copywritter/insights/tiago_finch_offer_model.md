# Tiago Finch — Aggressive Offer + Stack

> **Objective:** Apply aggressive offer logic (stack, real scarcity, execution) to maximize CVR and AOV.

## Overview

This document is a focused playbook on **Tiago Finch — Aggressive Offer + Stack**.

Primary job: apply aggressive offer logic (stack, real scarcity, execution) to maximize CVR and AOV.

- Focus: packaging and framing — the offer is the conversion engine (not the page design).
- Focus: structured testing, fast learning, and scaling with risk controls (not random budget changes).

## Key concepts

- Bonus stacks and high-perceived-value naming
- Urgency/scarcity and conditions (with integrity)
- How to use “aggressive” framing with clarity
- How to sustain it with proof and demonstration
- How to combine with paid traffic and scaling
- Common mistakes: hype without delivery and refunds

## Execution framework

1. **Define a strong, measurable promise**
   - Intent: Write the transformation in one line (before → after), with specificity.
   - Output: One sentence promise with a measurable criterion (timeframe, number, condition).
   - Pitfall: A vague promise (“grow”, “improve”) with no criteria or timeframe.
2. **Build the mechanism and minimum viable proof**
   - Intent: Collect real proof (screenshots, numbers, demos) and place it with context.
   - Output: A proof pack: 3–10 assets (screenshots, numbers, demos) mapped to key claims.
   - Pitfall: Using proof with no context (no baseline, timeframe, or attribution).
3. **Build a stack that covers objections**
   - Intent: List the top objections and map each to a fix (proof, stack item, guarantee, clarification) so the asset pre-empts doubt.
   - Output: An objection map (top 10) → one fix per objection (proof, bonus, guarantee, clarification).
   - Pitfall: Inventing bonuses/claims without mapping objections (the asset never resolves doubt).
4. **Anchor value before price**
   - Intent: Present price with calm confidence: tie it to anchored value, cost of inaction, and simple options (tiers/payment plans).
   - Output: A value-anchoring sequence: alternatives + cost of inaction + proof → price reveal.
   - Pitfall: Revealing price before value is anchored — sticker shock and low conversion.
5. **Present conditions (real scarcity/urgency)**
   - Intent: Use real constraints (time, capacity, bonuses, pricing rules) and state them clearly; avoid fake scarcity.
   - Output: A conditions policy: the constraint, how it’s verified, and what changes when the window ends.
   - Pitfall: Fake scarcity/urgency — short-term CVR, long-term brand damage and higher refunds.
6. **Optimize checkout and AOV (bump/upsell)**
   - Intent: Improve AOV/LTV with coherent expansion (bump/upsell/backend) so you can sustain higher CAC safely.
   - Output: An AOV/LTV improvement plan: bump/upsell/cross-sell/backend actions and tracking events.
   - Pitfall: Trying to raise AOV/LTV with unrelated add-ons — short-term revenue, long-term trust loss.
7. **Monitor refunds and align expectations/onboarding**
   - Intent: Reduce refunds by aligning promise ↔ proof ↔ delivery: tighten scope, set expectations, and pre-empt the main reasons people quit.
   - Output: An expectation-setting block: scope, timeline, effort required, and what “success” looks like.
   - Pitfall: Not setting expectations — you attract the wrong buyers and increase refunds.

## Aggressive offer reference (stack, conditions, AOV)

This section is a practical reference for building an aggressive stack without creating refund risk.

### Stack functions (avoid random bonuses)

- **Accelerate:** shortcuts, pre-built assets, templates (speed).
- **Simplify:** checklists, frameworks, scripts (less thinking).
- **Ensure:** support, reviews, feedback loops (risk reduction).

```text
Stack (template)
CORE: [main transformation]
+ Bonus (accelerate): [shortcut]
+ Bonus (simplify): [checklist/template]
+ Bonus (ensure): [support/review]
+ Guarantee: [scope + criteria]
+ Conditions: [deadline/capacity/bonus rules]
```

### Conditions menu (real urgency/scarcity)

- Capacity: limited seats/support bandwidth (explain what breaks if you over-sell).
- Deadline: bonuses/price/access rules change after a date (enforced by system).
- Behavioral: bonus unlock after action (reduces “freebie hunters”).

### AOV system (bump → upsell → downsell)

- Bump: one-click, low-friction, complements the core immediately.
- Upsell: buys speed/accountability (implementation), not random “more content”.
- Downsell: smaller scope/support for decliners (coherent, calm, not desperate).

## Common mistakes

- hype without delivery and refunds
- An aggressive promise without a mechanism (refund magnet).
- Fake urgency/scarcity (short-term CVR, long-term brand damage).
- Bonuses that compete with the core (decision friction).
- Price revealed before value is anchored (sticker shock).
- Optimizing visuals while ignoring payment friction (methods, approval rate).
- Bumps/upsells that feel unrelated (low take rate and trust loss).
- Overloading the checkout with copy (more reading = more doubt).
- Testing without a hypothesis (you can’t learn).
- Scaling budget before you have creative replenishment (frequency spikes).

## Tests and measurement

### Metrics

| Metric | What it indicates | How to use |
|---|---|---|
| AOV | Offer + upsell efficiency | Improve bump/upsell relevance, pricing, and placement. |
| CPA/CAC | Acquisition efficiency | Optimize by bottleneck; don’t scale what’s not stable. |
| Frequency | Saturation | Replenish creatives; expand audiences; control budget ramps. |

### Tests

- Test bonus naming: functional name vs “high perceived value” name (same bonus).
- Test stack order: objection-first bonuses vs acceleration-first bonuses.
- Test value anchoring sequence: alternatives/cost-of-inaction before price vs after.
- Test one variable at a time (angle OR hook OR proof) for clean learning.
- Scale horizontally first (new audiences) before vertical budget increases.
