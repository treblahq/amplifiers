# Frontend feature

> Compose design, React architecture, writing polish, and documentation follow-through for product-facing frontend work.

## Uses

- [designer](../../skills/designer/SKILL.md)
- [react-architect](../../skills/react-architect/SKILL.md)
- [humanizer](../../skills/humanizer/SKILL.md)
- [knowledge-writer](../../skills/knowledge-writer/SKILL.md)

## Use when

- Shipping a product-facing feature in a React codebase
- Refactoring a weak UI that has both UX and architecture issues
- Improving a screen that needs better structure, implementation, and copy

## Suggested order

1. Use `designer` to define hierarchy, layout, and interaction emphasis
2. Use `react-architect` to define components, hooks, and boundaries
3. Use `humanizer` to polish labels, helper text, and states
4. Use `knowledge-writer` if the feature changes documented behavior

## Output standard

- clearer feature structure
- implementation-ready frontend direction
- stronger microcopy
- minimal documentation updates when needed
