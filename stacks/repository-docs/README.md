# Repository docs

> Compose documentation, writing polish, structure, and presentation judgment for repository-facing documentation work.

## Uses

- [knowledge-writer](../../skills/knowledge-writer/SKILL.md)
- [humanizer](../../skills/humanizer/SKILL.md)
- [html-architect](../../skills/html-architect/SKILL.md)
- [designer](../../skills/designer/SKILL.md)

## Use when

- Reworking a project README
- Creating or improving contribution docs and writing standards
- Organizing repository documentation into a clearer structure

## Suggested order

1. Use `knowledge-writer` to define documentation ownership and structure
2. Use `humanizer` to improve tone and readability
3. Use `html-architect` when safe markup choices affect presentation
4. Use `designer` when visual hierarchy and first impression need work

## Output standard

- clearer documentation ownership
- improved entry-point docs
- stronger readability and scanning
- cleaner public-facing repository structure
